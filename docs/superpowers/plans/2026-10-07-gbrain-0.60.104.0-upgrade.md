# gbrain 0.60.104.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `0.60.104.0` a supported Mobrain gbrain pin: the host lane can plan, run, and roll back `0.50.5.0 → 0.60.104.0`, and the contract suite is green against that exact tag.

**Architecture:** One image swap to `oven/bun:1.4.2` + `gbrain` tag `v0.60.104.0`. The existing upgrade lane applies schema migrations and playbooks; it does not install the 104 intermediate images and it does not run `gbrain upgrade`. Every released tag in the window gets a registry row. Migration files are hand-translated. Writers that would start paid or file-rewriting defaults stay down until a host command resumes them.

**Tech Stack:** Bun, Docker Compose, the existing `scripts/upgrade.ts` lane, `src/upgrade/playbooks`, `src/contracts/registry.ts`, contract suite under `test/contract`.

**Spec:** `docs/superpowers/specs/2026-10-07-gbrain-0.60.104.0-upgrade-design.md`

## Global Constraints

- Target tag is `0.60.104.0`. Not `master`, not `latest`, not `0.60.105.0` (that tag does not exist).
- Never fork gbrain, never edit a gbrain checkout, never read gbrain tables, never screen-scrape human CLI prose, never invoke `gbrain` through a shell string.
- Never run `gbrain upgrade`, `gbrain self-upgrade`, or `gbrain autopilot --install`. `GBRAIN_SELF_UPGRADE_MODE=off` stays.
- `apply-migrations` in this lane always passes `--no-autopilot-install`. `--yes` alone is not acceptable at this target.
- An LLM may propose checklist text. It must not write `PlaybookStep.run` bodies. The person writing the spec reads `skills/migrations/v<version>.md` in the `v0.60.104.0` tree.
- Do not weaken `compareDoctor`. A previously-`ok` check that is not `ok` after the swap fails the run.
- Do not add a new `upgrade_runs.state` value. The hold is journal data on `gated_ok`.
- Do not move `.env.example`, the control-plane `ARG` default, `README.md`, or `docs/support-policy.md` until Task 9.
- Do not tag a Mobrain release, `docker push`, or backport onto `v1.0.0`.
- Do not implement schema-pack Phase B. Probe `schema active --source` and record the result. Leave the "no per-Space readback" copy in place.
- `HARNESS_VERSION` stays `2.1.274`. `docker/agent-runner.Dockerfile` stays `oven/bun:1.3.13`.
- Postgres image stays `pgvector/pgvector:pg16` unless Task 4's probe records `schema_version` not `ok`.
- CI: run suites locally. Dispatch `stack.yml` once, after Task 9 is green, and do not dispatch again to iterate. No `schedule:` triggers.
- Do not `git add .env`.
- Do not run `scripts/upgrade.ts run` or `rollback` against compose project `brainstand`. The fixture worktree sets `COMPOSE_PROJECT_NAME=gbrain-upgrade-fixture` and its `.env` is copied from `.env.example`, not from the real `.env`.

## Review Focus

These are the ways this jump hurts an operator even if the happy-path tests are green. Each one has a test on the task that owns it.

- `apply-migrations --yes` at this target authorizes an autopilot install. A green schema step that installed one is a failure. Test on Task 2.
- The schema journal must not claim "no migrations were pending" or cite the `0.50.0.0 → 0.50.5.0` byte-identical `migrate.ts`. Test on Task 2.
- A `gated_ok` event with `writers: 'held'` is an intentional pause, not a rollback. `status` saying rollback here would make an operator destroy a successful schema jump. Test on Task 3.
- `config get` redacts secrets and `postgres://` userinfo. `skillsPublished()` must not flip to false because the line became `***`. Test on Task 6.
- Resuming writers while a `blocksResume` item is `pending` starts fence rewrites and paid chronicle before the admin has read the banner. Test on Task 3.
- `/api/health` must not report the brain up because `serve --http` is in status-only mode. Test on Task 6, only if Task 4 shows that mode is reachable on our stack; otherwise the finding records "not reachable" and no health change is made.

```ts
    kind: 'hold-writers',
    from: 'gated_ok',
    reason: expect.stringContaining('resume-writers'),
  });
});

test('gated_ok without a hold is still rollback-required', () => {
  expect(resumeFrom([{ seq: 1, state: 'gated_ok' }]).kind).toBe('rollback-required');
});
```

- [ ] **Step 2: Run it and confirm it fails**

- [ ] **Step 3: Implement the hold**

Extend `resumeFrom` as in Interfaces. `statusOf` copies `data.writers` onto the record when `step === 'gated_ok'`.

When `run` opens any checklist item with `blocksResume: true`, the `gated_ok` event's `data` includes `writers: 'held'` and `reason: 'blocks_resume'`. Resume `gbrain-ops` and `control-plane` only. Print the `resume-writers` command. Do not enter `completed`.

When no item has `blocksResume`, behavior is unchanged: resume the full reverse order and enter `completed`.

`resumeWriters` is a new exported function the CLI dispatches on `resume-writers --run <runId>`. It does not rebuild images and does not move the pin. Opt-out application is an ops RPC call whose argv comes from the checklist item's `declineOp: { op: string; params: Record<string, string> } | undefined`. No shell string. If `declineOp` is absent, a `declined` item still blocks resume.

Do not add a state to `UPGRADE_RUN_STATES` or the SQL CHECK.

`test/unit/resume-writers.test.ts` builds a journal with one `blocksResume` item still `pending` and asserts `resumeWriters` throws and does not call the resume dependency. A second case, item `acknowledged`, asserts resume is called with exactly `['agent-runner', 'scheduler', 'gbrain-worker', 'gbrain-serve']` and a `completed` event is appended. Inject the resume function; do not start Docker in this test.

- [ ] **Step 6: Document the hold in the runbook**

In `docs/runbooks/upgrade.md`, state that `gated_ok` plus `writers: held` means the schema jump succeeded and writers are down on purpose. The next command is `resume-writers`, not `rollback`. Rollback remains the way back if the admin rejects the jump itself.
